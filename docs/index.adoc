`dogu` is a multiplatform command-line tool written in Go that seamlessly provisions and configures developer toolchains.
_Dogu_ is Korean for _tools_.

== Installation

The installer downloads the matching archive from the latest GitHub release
and installs `dogu` in `$DOGU_HOME/bin`. If `DOGU_HOME` is not set, this
defaults to `~/.dogu/bin`.

[source,bash]
----
curl -fsSL https://raw.githubusercontent.com/rahulsom/dogu/main/install.sh | bash
----

The Unix-like installer requires `curl`, `jq`, and `tar`. It prints the command
to add the install directory to the current shell's `PATH` if the directory
isn't already there. To choose another install directory, set
`DOGU_INSTALL_DIR` before running the script.

In Windows PowerShell, download and run the installer. It installs the
executable in `$DOGU_HOME\bin` (defaulting to `~/.dogu/bin`) and adds that
directory to your user `PATH`:

[source,powershell]
----
$installer = Join-Path $env:TEMP 'install-dogu.ps1'
Invoke-WebRequest https://raw.githubusercontent.com/rahulsom/dogu/main/install.ps1 -OutFile $installer
try {
    & $installer
}
finally {
    Remove-Item $installer -ErrorAction SilentlyContinue
}
----

The PowerShell installer updates `PATH` for the current session and future
terminals. Review the
link:https://github.com/rahulsom/dogu/blob/main/install.ps1[installer script]
before running it if you want to inspect what it does.

== Overview & Features

* **On-Demand Tool Provisioning:** Automatically downloads, unpacks, and registers candidate tool releases.
* **Environment Variable Automation:** Sets version-specific environment variables (e.g. `JAVA_17_HOME`, `JAVA_21_HOME`, `JAVA_HOME`, `NODE_24_HOME`, `NODE_HOME`) and prepends `PATH`.
* **Flexible Mirror Support:** Configure custom download mirror URLs via `config.json` files or environment variables.
* **Multiplatform Support:** Works across Linux, macOS, and Windows.

== Usage & CLI Flags

=== Command Syntax

Run any command prefixed with `dogu` and the desired tool or CLI flags:

[source,bash]
----
dogu [-v|--verbose] [--force] [--offline] [tools...] -- <command> [args...]
----

To update `dogu` itself to the latest released version:

[source,bash]
----
dogu self-update
----

NOTE: Self-update and version checking are enabled exclusively for official binary distributions (not when compiling/running directly from Go source code). When running as a binary distribution, `dogu` checks GitHub at most once every seven days and suggests running `dogu self-update` only when a newer release includes a compatible binary. The last check and available release are cached in `$DOGU_HOME/update-check.json` (defaulting to `~/.dogu/update-check.json`), including failed check attempts. Cached notices stop once the installed version reaches the available version. Running `dogu self-update` explicitly always checks GitHub immediately, bypassing the weekly cache.

Self-update verifies the downloaded release asset against the release's `checksums.txt` SHA-256 manifest before replacing the executable. If the manifest or checksum is missing or verification fails, the existing executable is left unchanged.

=== Flags

|===
| Flag | Description

| `-v, --verbose` | Enable verbose logging.
| `-f, --force` | Force re-downloading candidate versions even if already installed.
| `--offline` | Do not download tools; fail if a requested version is not installed.
| `--prerelease` | Include release candidates / pre-releases when resolving partial versions (default is `false`).
| `-h, --help` | Show usage information.
|===

=== Examples

Every tool accepts a major-only, major.minor, or exact version. Both
`--java 25` and `--java=25` select the newest matching installed candidate,
or install the newest matching release if none is installed.

An empty value (`--<tool>=`) selects the newest locally installed candidate
across all major versions, or installs the latest available release if none
is installed. Only dogu-managed candidates are considered, not tools on the
system `PATH`. Prereleases are excluded unless `--prerelease` is supplied;
`--force` skips local reuse and resolves a release online.

Use `--offline` to require all requested tools to already be installed in
`$DOGU_HOME`; no release discovery or downloads are performed. `--offline` and
`--force` cannot be combined.

[source,bash]
----
dogu --java= -- java --version
dogu --node= -- node --version
----

Use the explicit `=` for an empty version; a bare `--java` still requires
a version argument. Release discovery may still contact upstream registries
when a static download mirror is configured.

Run Maven tests with Java, Maven, and Node.js provisioned:

[source,bash]
----
dogu --java 21 --maven 3.9 --node 24 -- mvn clean test
----

Run Pytest with Python and UV provisioned:

[source,bash]
----
dogu --python 3.11 --uv 0.5 -- pytest
----

Install Node dependencies with pnpm:

[source,bash]
----
dogu --node 20 --pnpm 8.15 -- pnpm install
----

== Candidate Storage

Candidate binaries are cached and unpacked at `$DOGU_HOME/candidates`.
If `DOGU_HOME` is not set, `dogu` defaults to `$HOME/.dogu`.
